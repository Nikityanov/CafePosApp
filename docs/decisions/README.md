# Решения

Сюда вынесены объяснения, которые раньше лежали комментариями в коде. Перенос сделан
2026-10-07 при выполнении пункта «комментарии в `docs/decisions/`» из
[`../PLAN-architecture-debt.md`](../PLAN-architecture-debt.md).

## Как это устроено

- В коде осталась **одна строка-указатель** на этот раздел: `/// <remarks>Почему так — docs/decisions/….md</remarks>`.
  Без неё документ становится могилой: он есть, но на него никто не попадёт.
- Текст перенесён **дословно**. Переведена только разметка XML в markdown. Ничего не
  переписано и не переведено на другой язык — иначе при переносе теряется смысл.
- Короткие комментарии в 1–3 строки **остались в коде**. Они дешёвые, они рядом с
  кодом, и именно они раздувают файл.
- `/// <summary>` в одну строку остался: это API, он виден в IntelliSense.

## Честно о риске этого решения

Решение владельца. Документ прочитают реже, чем комментарий на своём месте. Ответ —
указатель в коде плюс этот индекс. Проверка, сработала ли схема, простая: если через
месяц вернётся баг, у которого здесь записано, почему его нельзя вернуть, — значит
схема не работает и решение надо пересмотреть.

## Чего здесь нет и почему

**`Core/`.** Там около 4 500 строк комментариев, в основном в `Core/Common` — это
пояснения к тем самым чистым решениям, которые вынесены из `MenuViewModel`. Они разбирают
свои файлы в порядке очереди, когда до них дойдёт очередь. Формат будет тот же.

**`MenuViewModel.Checkout.cs`.** Файл на 95 строк, его комментарии короче порога в
4 строки и остались на месте — переносить нечего.

**Тестовые файлы как критерий размера.** `CashReconciliationTests.cs` — один класс со
множеством кейсов. Делить по числу строк бессмысленно: количество тестов в классе не
делает его хуже. Критерий «нет файла > 500 строк» к тестам не применяется.
